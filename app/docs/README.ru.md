# SIMCom Serial AT Console

> [English](README.en.md) · [Español](README.es.md) · [Português](README.pt.md) · [Italiano](README.it.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · **Русский** · [中文](README.zh.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

Консоль **AT-команд** для сотовых модулей **SIMCom**, работающая целиком в браузере. Она общается с модулем через последовательный порт по **Web Serial API** — без установки — и включает **виртуальный режим** (встроенный эмулятор), чтобы проверять всё без оборудования.

Создана для семейства **A76xx / A7672SA**, с визуальными мастерами (*wizards*) для самых частых операций — сеть, данные, GNSS, SMS, email, телефонная книга, голосовые вызовы, TLS, файловая система, аппаратура, обнаружение глушения и другое — плюс «сырая» консоль для отправки любой AT-команды вручную.

> Справочник команд: *A76XX Series AT Command Manual* (V2.04).

## Возможности

- **100% в браузере**, без бэкенда и зависимостей. Просто откройте `index.html`.
- **Web Serial API** для связи с модулем по USB/UART.
- **Виртуальный режим**: встроенный AT-эмулятор, отвечающий на десятки команд (сеть, данные, GNSS, SMS, email, телефонная книга, голос, TLS, FS, аппаратура, глушение…), чтобы разрабатывать и показывать без платы.
- **Сырая консоль**: отправляйте любую AT-команду, с историей, автопрокруткой, отметкой времени и опциональным эхо.
- **Быстрые команды**, сгруппированные в боковой панели.
- **Визуальные мастера** для 20+ функциональных областей, с формами, живыми индикаторами, картами, SVG-графиками и разбором URC.
- **Макросы** с цепочками шагов, задержками, отправкой данных и управляющими символами (`Ctrl-Z`, `ESC`).
- **10 языков** (en, es, pt, it, fr, de, ru, zh, ja, ko).
- **Светлая / тёмная тема**.
- **Изменяемые мышью панели** (ширина и высота), двойной клик для сброса, и **развёрнутый** режим мастера.

## Требования

- Браузер на базе **Chromium** с Web Serial API: **Chrome**, **Edge** или **Opera** (десктоп).
  - Firefox и Safari в настоящее время **не** поддерживают Web Serial.
- Для подключения к оборудованию модуль должен предоставлять **последовательный порт** (USB-CDC или адаптер UART–USB), видимый в ОС.
- В Linux обычно нужны права на устройство (например, членство в группе `dialout`).

Node.js для работы консоли не нужен. Node используется только для [companion-библиотеки](#companion-библиотека-simcom-at-parser) и её тестов.

## Быстрый старт

1. Скачайте/клонируйте проект.
2. Откройте **`index.html`** в Chrome или Edge.
   - Работает как локальный файл (`file://`) или через статический сервер.
   - Если хотите раздать его:
     ```bash
     # простой вариант с Python
     python3 -m http.server 8080
     # затем откройте http://localhost:8080
     ```
3. Выберите язык и тему вверху справа.
4. Чтобы проверить без оборудования, включите **Virtual** (см. ниже). Для реального оборудования задайте параметры порта и нажмите **Connect**.

> ⚠️ **Встроенный предпросмотр в чате не работает**, потому что не загружает внешние `css/`, `js/` и `lang/`. Нужно **скачать ZIP и открыть `index.html` локально**.

## Виртуальный режим (без оборудования)

Включите переключатель **Virtual** в верхней панели и нажмите **Connect**. Консоль подключается к **AT-эмулятору**, который имитирует модуль (по умолчанию *A7672SA-FASE*) и отвечает на команды как реальная прошивка, включая асинхронные **URC**:

- Сведения о модуле, SIM, сети и сигнале.
- Открытие/закрытие сессии данных и IP.
- GNSS с NMEA-кадрами (`GSV`/`GGA`) для Sky View и карты.
- SMS (предзагруженный ящик, отправка с приглашением `>`).
- Загрузка сертификатов по длине в байтах (`CCERTDOWN`).
- Аппаратные показания (батарея, температура, АЦП, GPIO).
- Обнаружение глушения с периодическим URC `+SJDR:`.
- Email (SMTP) с полным потоком приглашения для темы/тела.
- Телефонная книга (предзагруженные записи, добавить/найти/удалить) и голосовые вызовы (набор → активен, отбой).

Это рекомендуемый способ изучить инструмент и проводить демонстрации.

## Подключение к реальному модулю

В верхней панели задайте параметры порта и нажмите **Connect** (браузер попросит выбрать последовательное устройство):

| Параметр | Варианты |
|----------|----------|
| **Baud**  | 9600 · 57600 · 115200 · 230400 · 460800 · 921600 |
| **Data**  | 8 · 7 |
| **Stop**  | 1 · 2 |
| **Parity**| None · Even · Odd |
| **EOL**   | CR · CRLF · LF (терминатор, добавляемый к каждой команде) |

Панель **состояния** показывает соединение (online/offline), порт, сигнал, регистрацию в сети и оператора.

> Смена **скорости** модуля (мастер UART → `AT+IPR`) разрывает текущее последовательное соединение: придётся переподключиться на новой скорости.

## Интерфейс

Экран разделён на три зоны, все **изменяемого размера**:

```
┌──────────┬───────────────────┬───────────────────────────┐
│ Sidebar  │  Мастер (wiz)     │  AT-консоль                │
│ (группы) │  (панель меню)    │  (лог + ввод команды)      │
└──────────┴───────────────────┴───────────────────────────┘
```

- **Верхняя панель**: параметры порта, язык, тема, переключатель Virtual и кнопка Connect.
- **Sidebar**: сгруппированные быстрые команды. Каждая группа со значком ⚙ открывает свой **мастер**.
- **Мастер**: центральная панель, открывающаяся выбранным меню. Имеет кнопки **развернуть** (⛶) и **закрыть** (✕).
- **Консоль**: лог сессии (с переключателями **TIME**, **SHOW ECHO**, **AUTO-SCROLL**), ввод AT-команд и отправка **макросов**.

### Изменяемые панели

- Перетащите **разделитель sidebar │ мастер**, чтобы изменить ширину боковой панели.
- Перетащите **разделитель мастер │ консоль**, чтобы изменить ширину мастера (или **высоту**, когда экран узкий и панели складываются стопкой).
- **Двойной клик** по разделителю сбрасывает эту панель к размеру по умолчанию.
- **Разворот** мастера расширяет его на ширину панели + консоли (консоль снизу, начинается в пропорции **60/40**); разделители продолжают работать.

### Макросы и управляющие символы

Макросы объединяют несколько команд. Поддерживаются:

| Токен | Действие |
|-------|----------|
| `@delay` | ожидание (настраиваемая задержка между шагами) |
| `>data`  | отправляет `data` после приглашения `>` |
| `^Z`     | `Ctrl-Z` (конец SMS / полезной нагрузки) |
| `^[`     | `ESC` (отмена) |

Каждый мастер также предлагает переключатель **«загрузить в редактор вместо выполнения»**, удобный для проверки команды перед отправкой.

## Мастера (wizards)

Каждая группа боковой панели может открыть мастер. Четыре протокольных (TCP/UDP, HTTP, FTP, MQTT) используют общую форму; остальные — это специализированные панели.

| Мастер | Что делает | Основные AT-команды |
|--------|-----------|----------------------|
| **Basics** | Сведения о модуле (модель, ревизия, IMEI, SIM, сигнал), эхо, уровень ошибок `CMEE`, и **Power/CFUN** (Full/Min/RF off/Reset). | `SIMCOMATI`, `CPIN?`, `CSQ`, `ATE`, `CMEE`, `CFUN` |
| **SIM** | ICCID/IMSI/SPN, разблокировка PIN, блокировка и смена PIN. | `CICCID`, `CIMI`, `CSPN?`, `CPIN`, `CLCK`, `CPWD` |
| **Network / signal** | Оператор, сигнал (dBm), регистрация, технология и PS-attach. Выбор **режима сети** с чтением и запросом поддерживаемых режимов. | `COPS?`, `CSQ`, `CEREG?`, `CGATT?`, `CNMP` |
| **Data** | Состояние сессии данных и IP, открыть/закрыть сессию, и APN (чтение/задание). | `NETOPEN?`, `IPADDR`, `NETCLOSE`, `CGDCONT`, `CGATT?` |
| **TCP / UDP / Ping** | Форма для сокетов и ping. | `CIPOPEN`, `CIPSEND`, `CPING`, … |
| **HTTP** | Форма HTTP(S)-запросов. | `HTTPINIT`, `HTTPPARA`, `HTTPACTION`, … |
| **FTP** | Форма FTP(S)-передач. | `CFTPSxxx` … |
| **MQTT** | Форма подключения и публикации MQTT(S). | `CMQTTxxx` … |
| **File System** | Браузер файлов модуля (список, вход, удаление). | `CFSGFRS`, `CFSWFILE`, `CFSDFILE`, … |
| **GNSS** | Питание/режим, запуск Cold/Warm/Hot, фикс (lat/lon/alt/HDOP/UTC), карта OSM, полярный **Sky View** SVG и полосы сигнала спутников (NMEA `GSV`). | `CGNSSPWR`, `CGPSCOLD/WARM/HOT`, `CGNSSINFO`, `CGNSSTST` |
| **LBS** | Локация по базовой станции + карта. | `CLBS` |
| **SMS** | Создание/отправка (приглашение `>` + `Ctrl-Z`), разобранный ящик и удаление. | `CMGS`, `CMGL`, `CMGD` |
| **TLS / Cert** | Список/удаление сертификатов, **загрузка PEM** (`CCERTDOWN` по длине в байтах) и настройка SSL-контекста (версия, authmode, CA). | `CCERTLIST`, `CCERTDOWN`, `CCERTDELE`, `CSSLCFG` |
| **Time / diag** | Ручные часы (календарь + часовой пояс), автоматический пояс, NTP и разрешение DNS. | `CCLK`, `CTZU`, `CNTP`, `CDNSGIP` |
| **Serial / UART** | Baud, фрейминг (`ICF`, напр. 8N1=`2,2`), управление потоком, sleep и CMUX, с чтением состояния. | `IPR`, `ICF`, `IFC`, `CSCLK`, `CMUX` |
| **Hardware** | Батарея, температура и АЦП с SVG-графиками; GPIO (IN/OUT, LOW/HIGH) и аларм напряжения с двуручковым слайдером. | `CBC`, `CPMUTEMP`, `CADC`, `CGDRT`, `CGSETV`, `CGGETV`, `CVALARM` |
| **Wi-Fi scan** | Сканирование точек доступа (BSSID, канал, сигнал). | `CWSTASCAN` |
| **Jamming** | Включение обнаружения, живой индикатор по URC (`+SJDR:`), и настройка (период, min RxLev, min каналов, URC при изменении). | `SJDR`, `SJDCFG` |
| **Email** | SMTP(S): сервер, аутентификация, составление (От/Кому/Тема/Тело) и **отправка** с URC результата. Только отправка SMTP (без POP3/IMAP). | `CSMTPSSRV`, `CSMTPSAUTH`, `CSMTPSFROM`, `CSMTPSRCPT`, `CSMTPSSUB`, `CSMTPSBODY`, `CSMTPSSEND` |
| **Телефонная книга** | Хранилище (SM/ME/DC/RC/MC/FD) с занято/всего, список/добавить/удалить контакты, поиск и свой номер. | `CPBS`, `CPBR`, `CPBW`, `CPBF`, `CNUM` |
| **Голосовые вызовы** | Живое состояние вызова (свободно/набор/входящий/в разговоре), набор/ответ/отбой, DTMF-клавиатура и переключатель АОН. | `ATD`, `ATA`, `CHUP`, `CLCC`, `CLIP`, `VTS` |

## Архитектура

**Интернационализация (`i18n.js` + `lang/*.js`).** Любой видимый текст — это **ключ**. Каждый язык регистрируется через `registerLang(code, name, dict)`, а UI разрешает через `t('ключ')`. Элементы с `data-i18n` переводятся автоматически; мастера используют `t()` при рендере и перерисовываются при смене языка.

**Последовательный транспорт (`serial.js`).** Оборачивает Web Serial API в транспорт с *framer* (собирает строки из потока) и **классификатором**, который различает финальные ответы (`OK`/`ERROR`), данные и незапрошенные **URC**. *VirtualPort* предоставляет тот же интерфейс, но подключает **AT-эмулятор** вместо физического порта.

**AT-эмулятор (виртуальный режим).** Хранит состояние (SIM, сеть, данные, сертификаты, GPIO, GNSS, глушение, SMTP, телефонная книга, вызовы…) и отвечает на каждую команду как реальная прошивка, включая приглашения (`>`), подтверждение по длине в байтах (сертификаты, email) и тайминговую выдачу URC (NMEA, глушение, результат вызова).

**Система мастеров (`data.js` + `app.js`).** Каждая группа быстрых команд может объявить `wiz:'id'`. При открытии монтируется центральная панель и выполняется её функция `render(host)` (или общая форма). Ключевые механизмы:

- `UI.sendCollect(cmd, {timeout})` → промис, собирающий строки до `OK`/`ERROR`.
- `UI.tap` → наблюдатель строк (для живых URC, напр. NMEA, `+SJDR:`, `RING`).
- `wizCleanup` → teardown активного мастера (останавливает таймеры/таппы) при закрытии или смене языка.

## Расширение консоли

**Добавить быструю команду.** В `js/data.js`, внутри соответствующей группы `QUICK`, добавьте запись `['ключI18n', "AT+КОМАНДА"]` (с `1` в конце, если нужны параметры). Добавьте текстовый ключ во все 10 файлов `lang/`.

**Добавить язык.** Создайте `lang/xx.js`, вызывающий `registerLang('xx', 'Имя', { ...все ключи... })`. Он должен покрывать тот же набор ключей, что и `en.js`.

**Добавить мастер.** В `data.js`: задайте `wiz:'мойId'` у группы и зарегистрируйте `{ id:'мойId', title:'...', render: (host) => renderМойId(host) }`. В `app.js`: напишите `renderМойId(host)` с использованием `UI.sendCollect`, `t()` и (при необходимости) `UI.tap`/`wizCleanup`. Для виртуального режима добавьте обработчики команды в эмулятор в `serial.js`.

> Рекомендуется при изменениях: проверить синтаксис (склеить весь JS и `node --check`), сверить согласованность i18n-ключей по 10 языкам, убедиться, что фигурные скобки CSS сбалансированы, и запустить тесты библиотеки.

## Companion-библиотека: `simcom-at-parser`

Репозиторий также включает **`simcom-at-parser`** (v0.1.0) — **Node.js**-библиотеку (ESM, async), которая разбирает AT-ответы модулей SIMCom A76xx/A7672SA: транспорт, *framer*, классификатор, *modem*, парсеры и сервисные слои (TCP, HTTP(S), MQTT(S), FTP(S), TLS, GNSS, SMS, FOTA…), с эмулятором для тестов.

```bash
npm test          # ~80 тестов
npm run example   # базовый пример
```

- **Node** ≥ 18.
- AT-эмулятор веб-консоли разделяет тот же дух, что и в библиотеке.

## Замечания по реальному оборудованию

Некоторое поведение зависит от модуля и SIM/сети; учитывайте это при переходе с виртуального режима на оборудование:

- **GNSS**: кадры `GSV` могут выходить из отдельного NMEA-порта, не из AT-порта, в зависимости от прошивки.
- **LBS / NETOPEN**: требуют зарегистрированную SIM, действительный контекст PDP/APN и доступную сеть.
- **ADC** (`CADC?`): сырое значение — не вольты; его нужно масштабировать.
- **Baud / CMUX / CFUN-reset**: меняют или обрывают последовательную сессию; придётся переподключиться.
- **TLS** (`CCERTDOWN`): объявленная длина должна **точно** совпадать с отправленными байтами PEM.
- **Jamming**: `mnl` (min RxLev) применяется только к GSM; для периодических URC-отчётов задайте `period > 0` и `detecstat = 1`.
- **Email**: требует активную сессию данных (APN/PDP); для SMTPS загрузите правильный CA-сертификат и настройте SSL-контекст (в меню **TLS/Cert**). Многие провайдеры (Gmail) требуют **пароль приложения**.
- **Голосовые вызовы**: требуют включённой поддержки голоса/кодека; некоторые варианты A76xx — *data-only* и отклоняют `ATD;`. АОН входящего появляется только если сеть его передаёт и `CLIP=1` активен.

## Известные ограничения

- Предпросмотр в чате не загружает внешние ресурсы: используйте локальный `index.html`.
- Web Serial требует безопасного контекста (`https://`, `localhost` или `file://`).
- Инструмент предназначен для **диагностики/разработки**; ряд команд меняет состояние модуля (сеть, сертификаты, NVRAM, baud). Используйте осмотрительно на продакшен-оборудовании.
